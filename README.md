# 合成大奶龙

一个可以用浏览器直接打开的合成类小游戏（电 → 奶蛋 → … → 奶龙 → 川）。移动端优先，纯 HTML + Canvas + 自研的位置约束物理，无构建步骤、无第三方依赖。

![玩法](https://img.shields.io/badge/操作-拖动选位·松手投放-orange) ![平台](https://img.shields.io/badge/适配-iOS%20%2F%20Android%20%2F%20桌面-green)

## 怎么跑起来

- **最简单**：双击 `index.html`，用 Chrome / Edge / Safari 打开即可（file:// 协议已验证可用）。
- **手机试玩**：把整个文件夹丢到任意静态服务器，或者用局域网访问：

  ```bash
  # 在本目录执行，然后手机访问 http://<电脑IP>:8080
  python -m http.server 8080
  ```

- **部署**：整个目录就是一个静态站点，Vercel / Netlify / 对象存储 / 任意 CDN 都行。

### 部署到 GitHub Pages 的注意事项

1. Settings → Pages → Source 选 `Deploy from a branch`，分支 `main`、目录 `/ (root)`。
2. **根目录的 `.nojekyll` 不要删**（避免 Jekyll 介入，也能保证以下划线开头的文件被发布）。
3. **文件名大小写必须和 `js/fruits.js` 里的完全一致**。Windows 本地不区分大小写，
   Pages 跑在 Linux 上区分——这是「本地好好的、上线后部分图片变渐变」最常见的原因。
4. 换素材后要**连 `js/assets-meta.js` 一起提交**（跑一遍 `python tools/build-meta.py` 重新生成），
   否则碰撞体还是按旧图轮廓算的。
5. 用自定义域名时保留 `CNAME`。

**推完代码线上还是旧版？** 先别怀疑缓存，按这个顺序查（这次就踩过）：

1. 打开仓库的 **Actions**，找 `pages build and deployment` 这次运行。
   构建（build）成功、**部署（deploy）失败**是常见情况——GitHub 那边偶发，
   页面上点 **Re-run failed jobs** 或者再推一个提交就会好，站点会一直停在"上一次成功"的版本。
2. 都成功但页面没变 → 打开 <https://synthesis.gwpp.beauty/?x=1> 看 `查看源代码`，
   `<meta name="build" content="...">` 就是你发布的那一版（每次改完顺手改一下这个标记最省事）。
3. GitHub Pages 的静态文件默认 `Cache-Control: max-age=600`（10 分钟），
   所以 `index.html` 里的 `css/js` 都带了 `?v=` 版本号 —— **改完记得把版本号也改掉**，
   否则老访客可能还在跑旧 JS。

页面会先显示「正在载入素材 x / 10」，**10 张全部就绪才放开操作**（加载期间点屏幕不会有反应）。
万一有文件取不到，加载页会停在原地并把缺失的文件名显示出来，刷新重试即可——不会带着缺图开始。

## 首屏为什么慢，怎么查

先量，别猜。打开 `你的网址/?debug=1`，左上角会显示：

```
TTFB 3200ms   HTML 3600ms
可玩 5200ms   请求 16 个   372KB
最慢 09-long.webp 780ms
```

- **TTFB 很大（几秒）**：是服务器/线路的问题，跟文件大小无关。GitHub Pages 在国内常这样，
  换托管或给素材挂 CDN 才有用（见下）。
- **KB 数很大（比如 9000KB）**：说明线上还是旧版本，重新部署。

### 已经做的三件事

1. **素材 9.4MB → 337KB**：720→600px 长边、WebP q82。最大那颗果子在 3 倍屏上仍是 1:1 像素。
2. **优先级 + 全部就绪才开局**：前 6 级用 `fetchPriority: high` 优先下载，
   其余并行；但**必须 10 张齐了才放开操作**，杜绝"某个等级显示成渐变"。
3. **利用浏览器缓存**：GitHub Pages 给静态资源 10 分钟 `Cache-Control`，十分钟内再次打开基本是瞬时的。

### 如果还是慢：给素材挂 CDN

`js/fruits.js` 里改一行即可（文件一个都不用挪，jsDelivr 能直接读这个仓库）：

```js
assets: {
  spriteBase: 'https://cdn.jsdelivr.net/gh/用户名/仓库名@main/assets/fruits/'
}
```

末尾斜杠别丢。jsDelivr **不需要注册账号**，公开仓库直接就能用。

现在默认就配了这个地址，并且做了**竞速**：CDN 超过 1.8 秒没回，就同时开始拉仓库里的本地文件，
谁先到用谁；CDN 直接失败则立刻回落本地。所以配错的代价最多是 1.8 秒，不会把开局拖垮。

但注意：实测这个仓库走 jsDelivr 会被 **301 跳回 `raw.githubusercontent.com`**
（还没进它的缓存时就会这样），那就等于没加速——`raw.githubusercontent.com` 在国内往往比 Pages 更慢。
换任何 CDN 之后都用 `?debug=1` 看一下 TTFB 再决定，别凭感觉。

免费且不用注册的备选：`https://cdn.statically.io/gh/用户/仓库/main/assets/fruits/`、
`https://rawcdn.githack.com/用户/仓库/main/assets/fruits/`（这两个在某些网络下不一定通）。
真要稳定，还是换托管（Cloudflare Pages / Vercel / Netlify，免费但要注册）。

## 玩法

- 按住屏幕左右拖动选落点，松手投放；电脑上鼠标移动即可选位，点击投放。
- 两个**相同**的果子碰到一起就合成上一级，并加分。
- 连续合成会触发连击加成（最高 ×2）。
- 果子堆过顶部虚线并停留约 1.3 秒即结束。
- 两个**最高级**果子相撞不会消失，而是**轮回**成最低级果子（同时给一大笔分数），可以接着往上叠。
- **掉落等级靠合成解锁**：开局只掉 1~3 级；合出 4 级之后，4 级才会进入掉落池，5 级同理。
  所以前期不会被高级果子"喂"到，节奏完全靠自己合出来（解锁时画面上会飘一行「掉落解锁 N 级」）。

## 素材替换（重点）

所有素材都在 `assets/fruits/`，当前是 10 张手绘 WebP，**直接替换成你自己的图就行**，不用改代码逻辑。

### 三步换图

1. 把图片放进 `assets/fruits/`（建议：正方形、透明背景、PNG / WebP / SVG）。
2. 打开 `js/fruits.js`，把对应等级的 `sprite` 改成新路径：

   ```js
   { name: '番茄', radius: 42, score: 20,
     sprite: 'assets/fruits/tomato.png',   // ← 改这里
     spriteScale: 1.10, spriteOffsetY: 0, rotate: true }
   ```

3. 刷新页面。如果新图看起来偏小或偏大，调 `spriteScale` 即可。

> **体积很重要**。原始素材是 1024~1300px 的大 PNG，10 张共 **9.4MB**，
> 手机上要十几秒才下载完，期间缺图的等级会显示成备用渐变色。
> 现在统一压成 720px 长边的 WebP（质量 90），**全套 524KB**。
> 换图后用同样的方式压一遍，或直接把 `sprite` 指向你的 png（也能跑，只是慢）。

> 加载时会**自动裁掉素材四周的透明留白**，所以你不需要手动切图，主体有多大就显示多大。
> 裁边框和碰撞形状记在 `js/assets-meta.js` 里（预计算好的），所以**双击打开和用服务器打开表现完全一致**。

### 三个美术参数

| 参数 | 作用 | 说明 |
| --- | --- | --- |
| `spriteScale` | 整体缩放 | 图形和碰撞体一起放大。**默认 1.0 时素材（裁掉透明边后）最长边 = 2×radius×spriteScale**，碰撞形状就是按这个尺寸算的。 |
| `spriteOffsetY` | 上下偏移 | 单位是「半径」，正数向下。**保持 0**：碰撞形状精确贴着素材轮廓，任何偏移都会让画面和碰撞错开（负=悬空，正=穿模）。 |
| `rotate` | — | **已废弃**。转向由物理决定（见下文「素材会转动」），单个果子不再单独控制。 |

### 关于异形素材

碰撞体不是「一个大圆」，而是**贴着素材轮廓铺的一圈内切小圆**：

1. 素材栅格化到 512、裁掉透明边，再缩到 256 的网格；
2. 对 alpha 做距离变换，得到每个实心点到轮廓的距离；
3. 贪心铺圆：每次挑「还没被盖住、且离轮廓最远」的点，用它到轮廓的距离当半径；
4. 再单独补几轮「残区补圆」，专治尾巴、耳朵这种又细又小、按面积永远排不上号的地方。

一颗果子通常 16~36 个圆，数据存在 `js/assets-meta.js`（全套 7.9KB）。

**为什么回到圆**：物理内核换成了位置约束（PBD），每次迭代只做一件事——在最近的一对圆上
把两颗果子按质量反比推开。圆算距离只要几次乘法；多边形得先求最小穿透轴，慢一个量级，
而一帧要算几十次。而「圆拼不出凹角」这个老问题，靠**小圆沿轮廓铺**就解决了：凹进去的地方
没有圆，小果子就是能待在那儿（那是素材上真实的空当），而轮廓本身被小圆盖住，不会陷进去。

**内切圆只会盖不满、不会鼓出去**，这一点很重要：

- 盖不满 → 两个果子贴得比看起来紧一点点（实测最深处 ≤2px，看不出来）
- 鼓出去 → 撑出一圈看不见的边，别的果子压在上面，就是「悬空感」

所以宁可多铺几个小圆，也不让圆的并集超出轮廓。

实测（`python tools/build-meta.py`）：

| 指标 | 数值 |
| --- | --- |
| 覆盖率 | 99.6% ~ 100% |
| 漏盖（最深误差） | ≤0.4%，最深处 1~2px |
| 外溢 | 平均约 1px 的一圈薄边 |
| 单张素材圆数 | 16 ~ 36 |

### 换了素材要重新生成形状数据

`js/assets-meta.js` 是按当前这 10 张图算的，**换了图就得重跑**（Python 3 + Pillow）：

```bash
python tools/build-meta.py            # 重新生成 js/assets-meta.js，并打印每张的圆数与误差
python tools/build-meta.py --preview  # 顺便把圆画到 tools/_preview/*.png，肉眼验收
```

脚本用的缩放逻辑和游戏里 `bake()` 完全一致，最后会把圆重新栅格化跟原图逐像素对比，
打印「覆盖率 / 漏盖 / 外溢 / 最深」四个数。漏盖大了会穿模，外溢大了会悬空；
两个数都离谱，通常是素材里带着半透明投影或大片留白，得先把这些去掉。

### 贴不贴？用 `?debug=1` 看碰撞体

打开 `index.html?debug=1`，每个果子会画出它真正的碰撞圆（粉色虚线）。
正常情况这些圆的外缘应该贴着角色边缘：

- 圆**鼓出**轮廓 → 相邻会留空、显得隔空相撞
- 圆**缩在**轮廓里 → 相邻会互相压

因为形状就是按素材轮廓算的，**`spriteScale` 保持默认就是最贴的**，它现在只负责整体缩放这颗果子。

### 增删等级

`fruits` 数组就是完整的水果链，**增删条目引擎会自动适配**（等级 = 数组下标）。
改完记得同步 `rules.spawnLevels`（前几级会掉落）和 `spawnWeights`（出现权重），长度要对得上。

## 「下一个」是怎么保证不走样的

界面上有 **三格队列**，顺序就是它们到手上的顺序：

```
current（手上） → nextLevel（右上角显示的，落下后立刻接手） → backup（备胎，补位用）
```

- 每次投放：手上这颗落下去 → `nextLevel` 到手上 → `backup` 顶上「下一个」的位置 → 再抽一颗当备胎；
  右上角只在**这一瞬间**变一次，之后不再跳；
- 所以「下一个」永远就是"你落下手上这颗之后**立刻**拿到的那颗"。
  （这里踩过坑：一开始把备胎直接塞进手上、chip 却换成新抽的那颗，等于显示的东西要隔一次才轮到，
  表现就是「下一个」老是慢一拍。）
- 以前是"落下去 → 等 340ms 冷却 → 才出现下一颗"，这 340ms 里手上是空的、而右上角已经翻过去了，
  看起来就是"下一个突然闪了一下"；现在没有空窗，冷却只限制投放频率，不影响出果；
- 右上角用 **canvas** 画（`sprites[]` 里已经烘焙好的那张，和场上同源），
  不用 `<img>` 加载另一条 URL —— 否则贴图走 CDN / 被缓存时，可能出现"显示的是一个、落下的是另一个"。

## 手感调参

都在 `js/fruits.js`：

```js
world:   { width, height, wall, dropY, deathY }   // 场地尺寸与死亡线
physics: { gravity, substeps, iterations, ... }   // 重力、弹性、摩擦、迭代次数
rules:   { spawnLevels, spawnWeights, spawnUnlock, spawnBaseLevels, firstLevel, maxRepeat,
           dropCooldown, dangerDwell,
           comboWindow, comboStep, comboMax,
           recycle }                              // 规则与连击
```

几个常用项：

- **游戏太难 / 太简单**：改 `world.height`（越矮越难）或 `deathY`（越小越难）。
- **果子掉得太快**：调小 `physics.gravity`（单位是 px/s²）。
- **堆叠有点软**：调大 `physics.iterations`（默认 6），或把 `substeps` 从 3 提到 4。
  代价是性能，`node tools/sim-check.js` 能看到单帧耗时。
- **弹性 / 手感**：`restitution`（果子之间）、`wallRestitution`（撞墙撞地）、
  `restThreshold`（撞击速度低于它就不反弹，调大更"闷"、堆得更稳）。
- **太容易滑**：调大 `friction`（默认 0.955，越接近 1 越不滑）。
- **角色歪得多 / 想让它几乎总站直**：调 `physics.upright`（默认 6，越大站直越快，
  设 `0` 则完全自由翻滚、可能倒立停住）。
- **合成判定太严 / 太松**：`mergePad`（默认 1.0px）。这是"贴到多近算撞上"的容差。
- **死亡判定太急**：调大 `rules.dangerDwell`（毫秒）。
- **开局第一颗**：`rules.firstLevel`，默认 `0`（最低级），保证一开局有得合。
- **老出一样的**：`rules.maxRepeat`，默认 `2`，即同一级最多连出 2 次，第 3 次会被强制换掉；设 `0` 关闭此规则。
- **前期太难 / 太简单**：`rules.spawnBaseLevels`（默认 `3`，开局就能掉 1~3 级）。
  调大它 = 一开局就能掉更高级、更容易；调小 = 更硬核。
- **想取消"靠合成解锁"**：把 `rules.spawnUnlock` 设成 `false`，就退回"按 `spawnLevels` 固定掉前 N 级"。
- **满级相撞怎么处理**：`rules.recycle`。默认 `0` 表示变回最低级（轮回）；改 `2` 就变回第 3 级；
  设成 `-1` 则变成「两个满级一起消失」。

`world.width / height` 是**外框尺寸（含壁厚）**，实际可玩区域 = `width - 2×wall` × `height - wall`（当前 360 × 560）。
改尺寸会同时改变难度，建议改完用 `?debug=1` 玩两局，再跑一遍离线体检。

## 一些实现细节

- **坐标系固定 384×584（外框）**，渲染时整体等比缩放到屏幕，所以手机、平板、桌面上的物理表现完全一致。
- **物理是位置约束（PBD）**：每帧 3 个子步 × 6 次迭代。每个子步先积分，然后反复做两件事——
  把小圆推出墙外、把互相压住的两个圆按质量反比推开——最后由位移反推速度。
  静止堆叠不抖，挤压时也不会「软塌」。
- **合成在约束迭代里判定**：同级、且最近的一对圆真的贴上了（间距 ≤ `mergePad`），当场标记、
  当场生成下一级。不依赖任何碰撞事件——事件是「这一帧新产生的接触」，漏一次就永远补不上；
  这里每帧拿几何重算，贴上了就是贴上了。
- **合成点天然被保住**：新果子质量 ∝ 半径²，比旁边的大一圈，位置投影按质量反比分配位移，
  所以被推开的几乎总是旁边小的那颗。没有「先算出谁能挪到哪」的规划，也就没有
  「c 被甩过 d 头顶」「大果子被顶进别人身体」这类事。
- **不存在「残留穿透」**：重叠是每次迭代都在消的，不是「事后再修一次」。
  实测 22 颗的场面里最深重叠 0.8px（合成瞬间那一两帧），稳定后 0.1px 级。
- **素材会转动，而且碰撞跟着一起转**：位置约束里带了转角自由度——每个果子有转动惯量
  （`I = ½ m r²`），挤压力作用在接触点上，偏心就会产生转动；撞墙时也用那枚贴墙小圆的
  边缘当接触点。**碰撞小圆是随刚体一起旋转的**（`syncParts` 里乘了 `cos/sin`），
  所以歪着的角色，它的碰撞形状也歪着，画面和物理永远同一个姿势。
- **停稳后会自动扶正**：`physics.upright`（默认 6）。只在「几乎不动」时接管角速度，
  把姿势慢慢转回最近的立正角度，翻滚、被挤、下落的整个过程完全不受影响；
  设成 `0` 就是完全自由翻滚（可以倒立着停住）。被卡在果子堆里的角色转不动，就保持歪着 ——
  这是真实的挤压，不是 bug。
- **撞击有挤压、合成有弹出**：撞得越狠压得越扁（`sq`/`sqA`，最多 20%），
  合成出来的果子 170ms 内从 86% 弹到 100%——两者都是纯画面，碰撞体一直是全尺寸，
  所以动画期间也不会出现「看着没碰其实顶着」。
- **静止时几乎没有开销**：位置约束收敛后速度自然归零，不需要额外的「冻结」开关
  （以前那套冻结是为了躲开 Matter 的残留穿透，现在没有这个前提了）。
- **素材在加载时一次性栅格化到 512px 画布并裁掉透明边**，之后每帧只做贴图。
- **绘制顺序按体积**：大果子先画、小果子后画。小果子常落在腿间、肚皮下的空隙里，
  压在腿上画会像"嵌进身体"，压在上层就是"待在空隙里"。
- **音效是 WebAudio 实时合成的**，没有音频文件，右上角可静音（状态存 localStorage）。
- 适配了 `env(safe-area-inset-*)` 刘海屏安全区，禁用了双击缩放与下拉刷新。
- 触控和鼠标走同一套 Pointer 事件：**电脑端鼠标悬停即可移动落点**，点击投放；手机端拖动选位、松手投放。

## 离线体检

```bash
node tools/sim-check.js            # 正常对局：穿模深度、合成次数、单帧耗时
node tools/sim-check.js --stress   # 挤满（每 0.2 秒塞一颗）
node tools/sim-check.js --merge    # 合成可靠性：每一级各放一对，看是不是都合出下一级
```

`--merge` 是最有用的一条：它逐级验证「贴上了就一定会合」，任何一级合不上都会直接标红。
当前结果：9 级全部正常，正常对局最深重叠 0.8px、平均 0.09px、单帧物理 0.11ms。
