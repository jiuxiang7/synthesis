# 合成大奶龙

一个可以用浏览器直接打开的合成类小游戏（电 → 奶蛋 → … → 奶龙 → 川）。移动端优先，纯 HTML + Canvas + Matter.js，无构建步骤、无网络依赖。

![玩法](https://img.shields.io/badge/操作-拖动选位·松手投放-orange) ![平台](https://img.shields.io/badge/适配-iOS%20%2F%20Android%20%2F%20桌面-green)

## 怎么跑起来

- **最简单**：双击 `index.html`，用 Chrome / Edge / Safari 打开即可（file:// 协议已验证可用）。
- **手机试玩**：把整个文件夹丢到任意静态服务器，或者用局域网访问：

  ```bash
  # 在本目录执行，然后手机访问 http://<电脑IP>:8080
  python -m http.server 8080
  ```

- **部署**：整个目录就是一个静态站点，Vercel / Netlify / 对象存储 / 任意 CDN 都行。

### 部署到 GitHub Pages 的注意事项

1. Settings → Pages → Source 选 `Deploy from a branch`，分支 `main`、目录 `/ (root)`。
2. **根目录的 `.nojekyll` 不要删**（避免 Jekyll 介入，也能保证以下划线开头的文件被发布）。
3. **文件名大小写必须和 `js/fruits.js` 里的完全一致**。Windows 本地不区分大小写，
   Pages 跑在 Linux 上区分——这是「本地好好的、上线后部分图片变渐变」最常见的原因。
4. 换素材后要**连 `js/assets-meta.js` 一起提交**，否则碰撞体还是按旧图轮廓算的。
5. 用自定义域名时保留 `CNAME`。

页面现在会先显示「正在载入素材 x / 10」，全部就绪才允许操作；
万一有文件 404，会直接把缺失的文件名列在屏幕上（并自动重试一次），不用猜。

## 玩法

- 按住屏幕左右拖动选落点，松手投放；电脑上鼠标移动即可选位，点击投放。
- 两个**相同**的果子碰到一起就合成上一级，并加分。
- 连续合成会触发连击加成（最高 ×2）。
- 果子堆过顶部虚线并停留约 1.3 秒即结束。
- 两个**最高级**果子相撞不会消失，而是**轮回**成最低级果子（同时给一大笔分数），可以接着往上叠。

## 素材替换（重点）

所有素材都在 `assets/fruits/`，当前是 11 张手绘 SVG，**直接替换成你自己的图就行**，不用改代码逻辑。

### 三步换图

1. 把图片放进 `assets/fruits/`（建议：正方形、透明背景、PNG / WebP / SVG）。
2. 打开 `js/fruits.js`，把对应等级的 `sprite` 改成新路径：

   ```js
   { name: '番茄', radius: 42, score: 20,
     sprite: 'assets/fruits/tomato.png',   // ← 改这里
     spriteScale: 1.10, spriteOffsetY: 0, rotate: true }
   ```

3. 刷新页面。如果新图看起来偏小或偏大，调 `spriteScale` 即可。

> **体积很重要**。原始素材是 1024~1300px 的大 PNG，10 张共 **9.4MB**，
> 手机上要十几秒才下载完，期间缺图的等级会显示成备用渐变色。
> 现在统一压成 720px 长边的 WebP（质量 90），**全套 524KB**。
> 换图后用同样的方式压一遍，或直接把 `sprite` 指向你的 png（也能跑，只是慢）。

> 加载时会**自动裁掉素材四周的透明留白**，所以你不需要手动切图，主体有多大就显示多大。
> 裁边框和碰撞形状记在 `js/assets-meta.js` 里（预计算好的），所以**双击打开和用服务器打开表现完全一致**。

### 三个美术参数

| 参数 | 作用 | 说明 |
| --- | --- | --- |
| `spriteScale` | 视觉大小 | **1.0 = 素材图形（裁掉透明边后）最长边正好等于碰撞直径（2×radius）**。默认值就贴合，想让果子看起来更“挤”可微调大 3%~8%。 |
| `spriteOffsetY` | 上下偏移 | 单位是「半径」。正数向下。叶子/果柄特别高的素材，用它把主体对回圆心。 |
| `rotate` | 视觉转动 | `true` 完全跟随物理旋转（360° 自由翻滚，落地什么姿势就是什么姿势）；`false` 完全不转。注意：走「贴形碰撞」的异形素材**必须 `true`**，否则碰撞体和画面会错位。 |

### 关于非圆形素材

碰撞体会**按素材轮廓自动拟合**：对 alpha 做距离变换，先在主体上铺一批内切圆（最多 26 个），
再补最多 4 个「细节圆」盖住脚、耳朵、尾巴、翅膀尖这些细突出物，拼成贴着图形走的复合刚体。
每个圆的半径 = 该处内切半径 **+ 固定外扩量**（不是按比例放大）——并集在轮廓边缘本来会内缩
一点点，补固定量正好抵掉，超出的部分始终只有约 2 世界像素。

两个容易踩的坑（都修了）：
- **不能用"面积占比"判圆**：狗这种圆乎乎的身形也能占到包围盒 73%，按占比判圆会用一个直径
  等于包围盒的大圆兜底，身体比圆小一圈 → 别的果子落在看不见的圆上，看着就是"悬空"。
- **画布最外一圈要当背景**：素材裁完边正好贴满画布，距离变换看不到网格外面的背景，
  会以为边缘离背景很远，在边上铺出半径过大的圆，整圈碰撞体比图形大一圈。

当前除两枚校徽（1 个圆）外，每个素材 27~30 个圆，轮廓覆盖率全部 **0.99~1.00**。所以：

- 四条腿的马、趴着的猪、带翅膀的鸡，碰撞体都会贴着它们的身形，不再是一个大圆。
- 真正接近圆的素材（比如两枚校徽）拟合时第一圈就全覆盖了，自然只剩 1 个圆，等于单圆，最稳最省。
- 整个过程全自动，**不需要你标注任何形状参数**。
- 形状数据在 `js/assets-meta.js` 里（预计算好的，10 个素材 ≈ 4KB）。
  这么做是因为 `file://` 双击打开时浏览器禁止读像素，现场算不出来就会退回「不裁边 + 单圆」，
  画面立刻出现空隙和穿模——这正是早期版本「明明换好素材却还是不对」的原因。

### 换了素材要重新生成形状数据

`js/assets-meta.js` 是按当前这 10 张图算的，**换了图就得重算**，否则会沿用旧图的轮廓。
在本地服务器下打开时程序会现场算一遍（读得到像素），所以不会崩，只是和双击打开不一致。
重算方法：把 `js/assets-meta.js` 挪走 → 用本地服务器打开 `index.html` → 
控制台执行 `copy(JSON.stringify(Object.fromEntries(Object.entries(__watermelon.sprites).map(([i,s])=>[GAME_CONFIG.fruits[i].sprite,{box:[s.box.x,s.box.y,s.box.w,s.box.h],circles:s.shape?s.shape.circles.map(c=>[+c.x.toFixed(4),+c.y.toFixed(4),+c.r.toFixed(4)]):[],cover:s.shape?s.shape.cover:null}]))))`
→ 把结果贴回 `window.SPRITE_META = { ... }`。

### 贴不贴？用 `?debug=1` 看碰撞体

换完素材打开 `index.html?debug=1`，每个果子会画出它真正的碰撞圆（粉色虚线，异形素材是多个）。

- 圆比图**大**（虚线在图形外面）→ 相邻会留空 → 调**小** `spriteScale`
- 圆比图**小**（图形超出虚线）→ 相邻会互相压 → 调**大** `spriteScale`

因为碰撞是沿轮廓铺的，一般情况下 **`spriteScale` 保持 1.0 就是最贴的**；
它现在的作用是「整体缩放这颗果子（图形+碰撞一起放大）」，不再是用来补空隙的妥协手段。

### 增删等级

`fruits` 数组就是完整的水果链，**增删条目引擎会自动适配**（等级 = 数组下标）。
改完记得同步 `rules.spawnLevels`（前几级会掉落）和 `spawnWeights`（出现权重），长度要对得上。

## 手感调参

都在 `js/fruits.js`：

```js
world:   { width, height, wall, dropY, deathY }   // 场地尺寸与死亡线
physics: { gravity, restitution, friction, ... }  // 重力、弹性、摩擦、迭代次数
rules:   { spawnLevels, spawnWeights, firstLevel, maxRepeat,
           dropCooldown, dangerDwell,
           comboWindow, comboStep, comboMax,
           recycle }                              // 规则与连击
```

几个常用项：

- **游戏太难 / 太简单**：改 `world.height`（越矮越难）或 `deathY`（越小越难）。
- **果子掉得太快**：调小 `physics.gravity`。
- **堆叠有点抖**：调大 `physics.positionIterations`（默认 12，代价是性能）。
- **异形果子太占性能**：把 `fitShape()` 里的 `MAXN` 从 26 调到 14、
  `MARGIN` 从 `SZ*0.012` 调到 `SZ*0.02`（圆更少但更大，代价是轮廓贴合度下降，细部会露出空隙）。
- **死亡判定太急**：调大 `rules.dangerDwell`（毫秒）。
- **开局第一颗**：`rules.firstLevel`，默认 `0`（最低级），保证一开局有得合。
- **老出一样的**：`rules.maxRepeat`，默认 `2`，即同一级最多连出 2 次，第 3 次会被强制换掉；设 `0` 关闭此规则。
- **满级相撞怎么处理**：`rules.recycle`。默认 `0` 表示变回最低级（轮回）；改 `2` 就变回第 3 级；
  设成 `-1` 则恢复成「两个满级一起消失」的老行为。

`world.width / height` 是**外框尺寸（含壁厚）**，实际可玩区域 = `width - 2×wall` × `height - wall`（当前 360 × 560）。
改尺寸会同时改变难度，建议改完用机器人验一遍。

注意：碰撞体现在是「按素材轮廓拼出来的」，改完参数建议直接在 `?debug=1` 下多玩两局看手感，
离线机器人脚本已经不再适用（它模拟不了复合刚体）。

## 目录结构

```
index.html            页面骨架 + HUD + 结算面板
css/style.css         移动端布局、安全区适配、按钮与面板样式
js/fruits.js          配置表：水果链、物理参数、规则（换素材主要改这里）
js/assets-meta.js     素材预计算数据：裁边框 + 贴形碰撞圆（换素材后重算，见上文）
js/game.js            主逻辑：物理、合成、渲染、触控、音效
lib/matter.min.js     物理引擎（本地化，离线可用）
assets/fruits/*.webp  游戏实际加载的素材（720px 长边、质量 90，全套 524KB）
assets/source/*.png   原始高分辨率 PNG（仅备份，不参与加载）
assets/icon.png       网页标签页 / 卡片图标（由 09-long 裁上半身生成，180 版给 iOS 主屏用）
.nojekyll             让 GitHub Pages 跳过 Jekyll 处理
```

## 一些实现细节

- **坐标系固定 384×584（外框）**，渲染时整体等比缩放到屏幕，所以手机、平板、桌面上的物理表现完全一致。
- **物理固定步长 60Hz**，掉帧时最多补 4 步，不会出现“卡一下然后炸开”。
- **碰撞体加厚到 400px**（视觉上壁只有 12px），杜绝高速下坠穿透墙体。
- **碰撞面比外框内缩一个壁厚**，墙体和果子永远不重叠，贴边贴底的果子不会被遮住。
- **素材在加载时一次性栅格化到 512px 画布并裁掉透明边**，之后每帧只做贴图，中低端手机也能稳住 60fps。
- **碰撞体按素材轮廓自动拟合**：alpha 距离变换 + 贪心铺内切圆（最多 7 个），组成复合刚体；
  真正圆形的素材拟合后就只剩 1 个圆。形状预先算好存在 `js/assets-meta.js`，
  所以 `file://` 双击打开也有完整的贴形碰撞，不会退化。
- **静态背景缓存**：容器底色和器壁只在尺寸变化时重画一次，每帧只是一次贴图。
- **静止冻结**：全场连续半秒没有可观察的位移/转角，就直接不跑物理（每帧只剩绘制），
  彻底消除"堆稳了还在高频微抖"，静止时 CPU 接近 0。投放、合成、重开都会立刻解冻。
  没有用 Matter 自带的单体休眠——它在"支撑它的果子被合成掉 / 自己滚走"之后不会醒，
  果子会冻结在半空，看起来就是悬空。
- **冻结的三个护栏**：① 解冻后至少再跑 0.8 秒物理（`wakeUntil`），否则"速度已很低但还压着"
  的瞬间会被冻住，穿透就永久留在画面上；② 冻结期间每隔 20 帧查一次物理接触对，
  发现有果子一个接触对都没有（真悬空）就立刻解冻；③ 贴近死亡线时不允许冻结，危险计时照走。
- **合成后主动分离**：新果子比原来两颗都大，经常直接把旁边的小果子"吞"进身体。
  被吞的小果子若陷在腿间这种凹槽里，四周碰撞圆受力对称，求解器永远推不出来，
  会一直挂着十几像素的穿透。所以合成后做一次 `separateOverlaps()`，
  沿连线把重叠的果子推出体外（实测把 12.8px 的残留压到 1px 以内）。
- **角度完全不限制**：素材会 360° 自由翻滚，落地什么姿势就是什么姿势。
- **绘制顺序按体积**：大果子先画、小果子后画。小果子常落在腿间、肚皮下的空隙里，
  压在腿上画会像"嵌进身体"，压在上层就是"待在空隙里"。
- **合成判定走物理碰撞事件**（`collisionStart`），不再用圆心距离——复合刚体没有「圆心」可言。
- **音效是 WebAudio 实时合成的**，没有音频文件，右上角可静音（状态存 localStorage）。
- 适配了 `env(safe-area-inset-*)` 刘海屏安全区，禁用了双击缩放与下拉刷新。
- 触控和鼠标走同一套 Pointer 事件：**电脑端鼠标悬停即可移动落点**，点击投放；手机端拖动选位、松手投放。
